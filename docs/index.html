Documentation: how the status figures are counted

This page defines every figure on the status page. It changes only when the way a figure is counted changes.

The canary

A scheduled check runs every 120 minutes. Each cycle sends one fresh run of the Google Trends actor through the customer path (a request from outside, through the gateway and a Cloudflare Worker, to the actor on Apify) on a rotating keyword, with the cache bypassed. Cycles that did not run, for example while our host was down, are not counted either way, so every figure covers the cycles that ran.

What counts as clean

A run is clean only when it returns at least 40 weekly points on the 12-month window, at least 5 top and at least 1 rising related queries, in under 90 seconds. A partial answer counts as a failure, as does any non-200 response.

First attempts only

A run is the first attempt of a scheduled cycle. A retry after a failure is not counted, because a retry hides the failure it follows. The log began recording first attempts at 2026-10-21 18:14 UTC; earlier rows logged only the retry and are not counted.

Windows

Last 24 hours, last 7 days and last 30 days are counted back from the time the page was generated, and the 7-day and 30-day boxes appear only when the log spans that long (the 24-hour box is always shown). When the newest reading is older than a window, the box says "no reading since" and that date, and prints no percentage. The per-day strip shows readings in the log for that UTC day, which can be more or fewer than 12.

The "From ... through ..." box

While the log is younger than 30 days, one box states both ends of the interval it covers: the first counted reading and the newest one.

Failures list

The newest failures among the counted readings, with time, keyword and what came back.

Store table

For each Tallyrake actor on Apify Store with more than 2 users in the last 30 days: the number of users, the number of runs by accounts other than ours, the share of those runs that did not fail, and the latest build. Success is 100 minus the failed share of those runs as Apify reports it; when Apify gives no failed share the cell says "not measured".

Limits

The canary tests one actor on one rotating keyword at a time; it is a sample, not every request. The Store figures cover runs by other accounts on the Store and are read from Apify's own counters.
